NEGATIVE TEST FRAMEWORK VERIFICATION
-----------------------------------
Negative tests are identified by the presence of a .error file
(without a corresponding .expected file).

Workflow:
1. Compile the source file (expecting failure)
2. If compilation succeeds → test FAILS (expected failure didn't occur)
3. If compilation fails → read .error file for expected pattern
4. Check if actual error message contains the expected pattern
5. If yes → test PASSES, if no → test FAILS with mismatch details

FRAMEWORK DESIGN
---------------
run_negative_test() handles:
  - Compilation failure detection
  - Expected error pattern matching
  - Detailed error message mismatch reporting

Example negative test case files:
  - source.kl (malformed Klang code)
  - source.error (expected error message pattern)

VERIFICATION
------------
Framework code verified:
  - Negative test path is correctly identified via .error file existence
  - Compilation success (unexpected) is flagged as test failure
  - Error pattern matching is case-sensitive substring match
