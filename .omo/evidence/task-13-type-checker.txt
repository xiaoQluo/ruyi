Task 13: Pattern Matching - Type Checker Implementation

## Summary

Implemented pattern matching support in the type checker and code generator for the Klang compiler.

## Files Modified

### 1. typechecker/diagnostics.rs
Added new diagnostic kinds for pattern matching:
- NonExhaustiveMatch: Reports when match expression doesn't cover all cases
- RedundantPattern: Reports when a pattern can never match (duplicate)
- PatternTypeMismatch: Reports when pattern can't match value type
- InvalidPattern: Reports malformed patterns

Added corresponding messages in DiagnosticKind::message().

### 2. typechecker/patterns.rs (NEW)
Created new module for pattern analysis:
- PatternAnalysis struct with is_exhaustive, missing_cases, has_redundancy, redundant_arm
- analyze_patterns() function for exhaustiveness and redundancy checking
- pattern_covered_cases() to compute which cases a pattern covers
- find_missing_cases() to determine uncovered cases
- is_refutable() to check if pattern can fail to match

### 3. typechecker/mod.rs
Added `pub mod patterns;` to export the new patterns module.

### 4. typechecker/inference.rs
Updated Statement::Match handling to:
- Call patterns::analyze_patterns() on match arms
- Report NonExhaustiveMatch error when match is not exhaustive
- Report RedundantPattern warning when a pattern is redundant

## Implementation Details

### Exhaustiveness Checking
The analyzer tracks which cases are covered by each pattern:
- Wildcard `_` covers all cases
- Literal patterns cover specific values
- Identifier patterns bind values
- OR patterns combine coverage sets
- Object/array patterns check field/element coverage

### Redundancy Checking
Tracks which cases have already been covered. When a case is covered multiple times, the second occurrence is flagged as redundant.

### Type Binding
The existing bind_pattern_type() function handles:
- Identifier patterns: declare variable with matched type
- Wildcard: no binding
- Literal: type check at runtime
- Object patterns: recursive binding for each field
- Array patterns: element-wise binding with rest support
- As patterns: bind inner then rebind with alias
- Or patterns: bind first alternative

## Pattern Types Supported

1. Wildcard `_` - matches anything, no binding
2. Identifier `x` - matches anything, binds to x
3. Literal `1`, `"hello"`, `true`, `null` - exact match
4. Or `1 | 2` - matches either pattern
5. As `p as x` - matches p and binds to x
6. Object `{ x, y: n }` - destructure object fields
7. Array `[first, ...rest]` - destructure array elements
8. Rest `...rest` - collects remaining elements
