Async Runtime Fixes - klang_runtime/src/async_runtime.rs
============================================================
Date: 2026-05-02

Original Errors
---------------
1. error[E0107]: struct takes 2 generic arguments but 1 generic argument was supplied
   - 2 occurrences at lines 435 and 449
   - Cause: JoinAll was refactored from `JoinAll<F>` to `JoinAll<F, T>` but a duplicate
     `impl<F> JoinAll<F>` block was left behind.

2. error[E0592]: duplicate definitions with name 'new'
   - Occurred at line 399 (and line 439)
   - Cause: Two `impl` blocks both defined a `new` method for JoinAll.

3. error[E0282]: type annotations needed
   - Occurred at line 468
   - Cause: The old `impl<F> JoinAll<F>` block had `results: (0..n).map(|_| None).collect()`
     where the compiler could not infer the type for `None`.

Fixes Applied
-------------
1. Removed the stale duplicate `impl<F> JoinAll<F>` block (lines 435-473 in original).
   This single removal fixed E0107, E0592, and E0282 simultaneously.
   The remaining `impl<F, T> JoinAll<F, T>` block (with `F: KlangFuture<Output = T>`)
   is the correct, complete implementation.

2. Fixed inline test Waker constructions: changed `task_id: 0` to `task_id: TaskId(0)`
   in 3 test cases (test_join_all, test_race, test_yielding_future).

Additional Pre-existing Changes
--------------------------------
- `test_waker` helper method was already present on `Scheduler`.
- Integration tests in `tests/async_runtime.rs` were already updated to use
  `scheduler.test_waker(TaskId(0))` instead of direct `inner` field access.
