Task 13: Pattern Matching - Code Generator Implementation

## Summary

Implemented code generation support for pattern matching in the Klang compiler.

## Files Modified

### 1. codegen/patterns.rs (NEW)
Created new PatternCompiler struct for pattern code generation:

#### Key Functions:

##### compile_match()
Main entry point for compiling match expressions. Dispatches to specialized
methods based on scrutinee type:
- compile_primitive_match(): int, float, string, bigint
- compile_bool_match(): boolean matching
- compile_null_match(): null matching
- compile_array_match(): array destructuring
- compile_object_match(): object destructuring
- compile_nullable_match(): T? matching (null check + inner match)
- compile_named_match(): enum/union type matching
- compile_dynamic_match(): dynamic type dispatch

##### generate_destructuring()
Generates code for destructuring a pattern against a value:
- Identifier: store value in variable
- Wildcard: discard value
- Literal: equality check
- Object: field access + recursive destructuring
- Array: index access + recursive destructuring
- Rest: slice remaining elements
- As: inner destructuring + alias rebind
- Or: try each alternative in sequence

### 2. codegen/mod.rs
Added:

## Code Generation Strategy

### Primitive Types (int, float, string)
Generate a switch/jump table for literal values. Fall through to wildcard
case if no match.

### Boolean
Special-case true/false matching. Generate conditional branches.

### Nullable Types
1. Generate null check first
2. If null, jump to null arm (or default)
3. If not null, unwrap and match on inner type

### Array Patterns
1. Check array length
2. For fixed-length patterns, verify exact length
3. For rest patterns, extract remaining elements
4. Generate element-wise matching

### Object Patterns
1. For each field in pattern:
   - Access field from scrutinee
   - Generate matching code for field pattern
2. Handle rest patterns by extracting remaining fields

### Guard Conditions
Guard conditions (if guards) are parsed but code generation
is not yet implemented. The AST supports arm.guard field.

## LLVM Integration Points

The PatternCompiler uses a BlockBuilder trait to interface with LLVM:
- build_store(): Store value to variable
- build_branch(): Unconditional jump
- build_cond_branch(): Conditional jump
- build_load(): Load from variable
- build_struct_gep(): Access struct field
- build_call(): Call runtime helper
- build_icmp(): Integer comparison

Currently the implementation is structural - full LLVM integration
would require deeper builder integration.
