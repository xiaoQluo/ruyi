# Task 10: dyn Trait Coercion - Evidence

## Date: 2026-05-04

## Issue
`let y: dyn Printable = "hello"` fails with "Type mismatch" even though string implements Printable.

## Root Cause
The `check` method in `inference.rs` (line ~1030) was using `is_consistent_with` for type checking.
When the expected type was `Type::Trait` (dyn Trait) and the synthesized type was `Type::String`,
the `is_consistent_with` call failed because `String` is not a subtype of `Trait` through the normal subtyping rules.

The `TraitRegistry::implements` method existed but was not being consulted during type checking.

## Fix Applied
Added special case in `check` method to handle concrete-to-trait coercion:

```rust
// Special case: concrete type -> dyn Trait coercion
// Allow concrete-to-trait assignment when the concrete type implements the trait
if let Type::Trait(trait_name) = expected {
    if self.trait_registry.implements(&synthesized, trait_name) {
        return synthesized;
    }
}
```

## Files Modified
- `crates/ruyic/src/typechecker/inference.rs` (line ~1030-1036)

## Verification
- Code compiles (rust-analyzer shows no errors)

## Example from traits.ry
```ruyi
let y: dyn Printable = "hello";  // Now works if string implements Printable

```

## TraitRegistry.implements Method (already existed)
```rust
pub fn implements(&self, ty: &Type, trait_name: &str) -> bool {
    match ty {
        Type::Named(name) | Type::Generic { base: name, .. } => self
            .type_trait_impls
            .contains_key(&(name.clone(), trait_name.to_string())),
        Type::String | Type::Int | Type::Float | Type::Bool => self
            .type_trait_impls
            .contains_key(&(ty.to_string(), trait_name.to_string())),
        Type::Dynamic | Type::Error => true,
        _ => false,
    }
}
```
