Task 4: Fix async arrow function parsing
==========================================

Change: Allow `async (params) => expr` without requiring `fn` after `async`.

File Modified: crates/ruyic/src/parser/parser.rs

Change Details:
- In `parse_primary` method, `Some(Token::Async)` handler (line 1365):
  - Added `else if self.check(&Token::LParen)` branch after existing `self.check(&Token::Fn)` check
  - New branch calls `self.parse_primary()` to parse parenthesized params (returns Expr::Grouping)
  - Then checks for `=>` via `self.match_token(&Token::FatArrow)`
  - If found, converts params via `expr_to_arrow_params()`, optionally parses return type, parses body (block or expression), and returns `Expr::ArrowFunction { is_async: true }`
  - If `=>` not found, returns error "expected '=>' after async parameters"
  - Fallback error changed to "expected 'fn' or '(' after 'async'"

Verification:
- cargo check -p ruyic: ✅ Passes cleanly (only pre-existing warnings)
- cargo test -p ruyic --test parser: 144 passed, 11 pre-existing failures (unrelated - Builtin vs Identifier type representation)
- Key passing tests: test_expr_function_async, test_expr_arrow_block, test_expr_arrow_grouping, test_expr_arrow_single_param

Supported Syntax:
- `async (x) => x + 1`        // async arrow with single param
- `async (x, y) => x + y`     // async arrow with multiple params
- `async (x) => { return x; }` // async arrow with block body
- `async fn foo() { }`        // still works (unchanged)

What was NOT changed:
- `async fn` parsing behavior (untouched)
- Arrow function handling in `parse_expr_bp` (untouched)
- Any other part of the parser or other modules
