## Context

### Original Request
测试失败的进行修复计划编制，修复使用v0.5.1版本

### Interview Summary
**Key Discussions**:
- Strategy: Fix compiler bugs only. Unimplemented features (Power, --test, Timestamp/Random) stay as expected failures.
- Power operator, --test flag, Timestamp/Random: ACCEPT as expected failures
- v04 WIP files: Fix codegen (user explicitly requested)
- Version: v0.5.1 patch release from current v0.5.0 binary (align all version strings)
- Full release process: version strings, roadmap update, tag, commit

**Research Findings** (from 2 explore agents + direct analysis):
- 10 compiler bugs identified across parser, typechecker, codegen, linker
- `from` is a reserved keyword with no semantic use — blocks parameter names
- Parser supports only single `catch` clause — needs `Vec<CatchClause>`
- Function type `fn(): int` uses `:` where parser expects `->` (FatArrow)
- `dyn` as bare type (`let x: dyn = 42`) not handled by parser
- Null assertion `!` has no postfix operator support in parser
- `async` without `fn` before arrow function not allowed
- Match arm blocks require semicolons after expressions
- `compile_add` handles `string + string` but not `string + int/float`
- `dyn Trait` type recognized but coercion fails in typechecker
- `__gxx_personality_v0` not linked (missing `-lstdc++`/`-lc++`)

### Metis Review
**Identified Gaps** (addressed):
- Platform-specific linker flags: macOS needs `-lc++`, Linux needs `-lstdc++` → detect platform
- AST breaking change scope: Multi-catch propagates to parser, AST, codegen → documented in T7
- Expected failures tracking: Added EXP_FAIL status to baselines.json → T12
- Version discrepancy: main.rs says 0.4.1, binary says 0.5.0 → resolved to v0.5.1
- v04 files existence: Confirmed — `v04_minimal.ry`, `v04_simple.ry`, `v04_features.ry` all exist
