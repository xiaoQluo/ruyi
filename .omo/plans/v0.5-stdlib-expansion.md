## Context

### Original Request
Develop v0.5 of the Ruyi language compiler — the "Standard Library Expansion" phase. Make Ruyi capable of writing real programs with a functional standard library covering math, time, JSON, random, formatting, testing, regex, binary buffers, and network I/O.

### Interview Summary

**Key Discussions**:
- **Priority**: Fix existing stdlib backend wiring FIRST, then add new modules. Existing stdlib is non-functional (136 builtin calls = ~47 unique functions with ZERO backend).
- **Scope**: ALL 12 roadmap tasks included (P0 through P2). No CI/CD (deferred).
- **__builtin_* strategy**: Central registry — create a `BuiltinRegistry` that maps `__builtin_*`/`__io_*`/`__string_*`/`__path_*`/`__process_*` names to C runtime exports.
- **@test attribute**: Full compiler-level — parser/AST changes, annotation scanner, harness codegen, `ruyi test` CLI.
- **net.ry**: TCP + UDP (both protocols).
- **Test strategy**: Tests after implementation, integration tests (.ry + .expected files).

**Research Findings**:
- CRITICAL: `compile_call` in `codegen/expr.rs` resolves builtins via `module.get_function(&name)` using the **exact .ry source name** (e.g., `__builtin_str_len`). Runtime exports are named `ruyi_str_*` (different convention). No name mapping exists → nothing resolves.
- CRITICAL: `class Array<T> { let mut elements: Array<T>; }` in `collections.ry` — recursive field type will break class codegen.
- `parse_annotations()` exists but only called for class declarations, NOT functions. `@test fn` needs parser changes.
- Memory ownership undefined: strings returned by builtins use `std::alloc::alloc` (not GC-tracked) → potential leaks.
- `print` is special-cased in `compile_call` (hardcoded `if name == "print"`). `stdlib/io.ry` defines `fn print(value) { __io_print(value); }` — dead code.
- 28 C runtime exports exist: string conv, array/object alloc, GC, exceptions, async. No math/time/random/map/set/buffer/net.
- Float (f64) codegen is FULL (literals, arithmetic, comparison, int promotion). Math intrinsics are ZERO.
- `main.rs:50` has version string bug (`"v0.1.0"` should be `"0.4.1"`).

### Metis Review

**Key Findings**:
1. "136 builtins" is inflated — actual ~47 unique unimplemented functions in existing stdlib
2. Naming mismatch is the ROOT CAUSE of all builtin failures — `__builtin_int_to_str` ≠ `ruyi_int_to_string`
3. Array recursive field (`let mut elements: Array<T>`) breaks codegen
4. `parse_annotations()` must be wired to function declarations before @test work
5. Memory ownership contract must be defined (GC vs malloc for builtin returns)
6. Math builtins should use LLVM intrinsics (`llvm.sin.f64`, etc.) instead of C calls for performance

**Guardrails Applied**:
- MUST NOT implement HTTP/TLS in net.ry (TCP+UDP only)
- MUST NOT write custom regex engine (bind to `regex.h` or `regex` Rust crate via C-ABI)
- MUST NOT change CLI from flat flags to subcommands (defer to v0.6)
- MUST NOT break existing integration tests
- Math via LLVM intrinsics, time via system clock, random via PRNG (not crypto)
