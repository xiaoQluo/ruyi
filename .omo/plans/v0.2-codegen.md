# v0.2 代码生成补全计划

## TL;DR

> **Quick Summary**: 完成 Ruyi 编译器代码生成模块的 13 个缺失特性，使语言能够编译运行类、对象、数组、for 循环、try/catch、match 等非平凡程序。同时添加所需的运行时函数到 ruyi_runtime。
>
> **Deliverables**:
> - 13 个代码生成特性完整实现（类布局/成员访问/对象字面量/数组字面量/字符串拼接/for 循环/break-continue/try-catch/throw/match/模板字面量/BigInt/方法调用）
> - 5 个新运行时函数（string_concat, array_alloc, object_alloc, bigint_from_str, member_access）
> - 13+ 个集成测试（.ry + .expected 夹具）
> - 测试基础设施文件（tests/codegen.rs）
>
> **Estimated Effort**: Large
> **Parallel Execution**: YES — 3 implementation waves, max 7 concurrent
> **Critical Path**: Runtime foundation → Class layout → Member access → Method call

### Interview Summary

**Key Discussions**:
- 测试策略：TDD（先写测试 RED，再实现 GREEN，最后重构 REFACTOR）
- 执行策略：按特性分组并行（OOP 组、控制流组、表达式组）
- 运行时函数：v0.2 包含运行时函数实现（不推迟到 v0.3）
- 测试产出：集成测试 .ry 文件（不包含 Rust 单元测试）
- 异常处理：完整 LLVM invoke/landingpad 架构
- OOP 组：共享接口设计先行，然后全部并行

**Research Findings**:
- 全部 13 个任务的代码生成当前都是 STUB 或 ABSENT
- 运行时库（ruyi_runtime）异常处理、ARC、GC 已完善，仅缺代码生成桥接
- 驱动程序（driver.rs）无 AST 降级逻辑 — for 循环需直接生成 LLVM IR
- 字符串/对象/数组在 LLVM 中均为 `*i8` 不透明指针
- 泛型函数体当前不生成代码（单态化缺口），但 v0.2 任务不涉及泛型
- LLVM 未安装在当前环境，`cargo test --workspace` 无法运行

### Metis Review

**Identified Gaps** (addressed):
- **for 循环悖论**: `loops.ry` 含 for 循环但代码生成无处理器 → 确认为已知缺口，T1.5 将实现
- **运行时边界**: 4 个任务需新运行时函数 → 确认 v0.2 包含运行时实现
- **单态化缺口**: 泛型函数体未编译 → v0.2 任务不涉及泛型数组/类，排除此风险
- **OOP 内部依赖**: 类布局是前置条件 → 共享接口设计先行，然后全部并行
- **PatternCompiler**: 440行骨架未连接 → match 编译为链式 if-else，不使用 PatternCompiler
- **字符串表示**: `*i8` 不透明指针 → 接受现状，运行时函数操作指针

## Work Objectives

### Core Objective
完成代码生成模块的 13 个缺失特性，使 Ruyi 编译器能端到端编译运行使用类、对象、数组、for 循环、try/catch、match 等语言特性的程序。

### Concrete Deliverables
- `crates/ruyi_runtime/src/` — 5 个新运行时函数
- `crates/ruyic/src/codegen/builtins.rs` — 5 个新运行时函数声明
- `crates/ruyic/src/codegen/types.rs` — 对象/数组 LLVM 类型映射
- `crates/ruyic/src/codegen/expr.rs` — 7 个新表达式处理器
- `crates/ruyic/src/codegen/stmt.rs` — 6 个新语句处理器
- `crates/ruyic/src/codegen/decl.rs` — compile_class 实现
- `crates/ruyic/tests/codegen.rs` — 测试基础设施（新增文件）
- `crates/ruyic/tests/integration/cases/codegen/` — 13+ 个新集成测试夹具

### Definition of Done
- [ ] 全部 13 个代码生成特性在 `--check` 模式下通过类型检查
- [ ] 全部 13 个特性的 `.ry` 集成测试夹具通过（编译+运行+输出匹配）
- [ ] 5 个已有代码生成集成测试无回归（arithmetic, function_call, if_statement, print_int, while_loop）
- [ ] `cargo check --workspace` 通过
- [ ] `cargo test -p ruyi_runtime` 通过（新运行时函数测试）
- [ ] 每个特性至少 1 个 happy path + 1 个 error/edge case 测试

### Must Have
- 类布局：struct 类型定义、字段偏移、`new` 构造器
- 对象字面量：`{ key: value }` 编译为运行时结构
- 数组字面量：`[1, 2, 3]` 编译为运行时数组，索引访问
- 成员表达式：`obj.prop` 和 `obj?.prop` 代码生成
- 方法调用：`obj.method(args)` 含 `self` 绑定
- 字符串拼接：`+` 运算符支持字符串
- for 循环：C 风格 `for`（`for-in`/`for-of` 可选）
- break/continue：使用现有 `loop_stack`
- try/catch/finally：完整 LLVM invoke/landingpad
- throw 表达式：映射为 `ruyi_throw` 调用
- match 语句：编译为链式 if-else
- 模板字面量：`` `Hello ${name}` `` → 字符串拼接
- BigInt 字面量：`100n` → 运行时 bigint 类型

### Must NOT Have (Guardrails)
- **禁止修改**: 解析器（parser）、类型检查器（typechecker）、宏展开器（macro_expand）、词法分析器（lexer）
- **禁止实现**: 继承、vtable、原型链、动态属性添加
- **禁止实现**: `for-in`/`for-of` 遍历协议（仅 C 风格 for）
- **禁止实现**: 优化（`-O1`/`-O2`）、调试信息（DWARF）、async 状态机降级
- **禁止实现**: 运行时库链接（v0.3 任务）、GC 对接（v0.3 任务）
- **禁止重构**: 现有代码生成架构（保持 expr.rs/stmt.rs 模式）
- **禁止添加**: 路线图 13 个任务之外的特性
- **禁止使用**: 未连接的 PatternCompiler 骨架（match 直接用 if-else）

## Verification Strategy

### Test Decision
- **Infrastructure exists**: YES（cargo test + criterion，但 LLVM 不可用）
- **Automated tests**: TDD（先写集成测试 .ry 夹具，再实现代码生成）
- **Framework**: Rust `#[test]` + 集成测试运行器 `tests/integration/runner.rs`
- **TDD**: 每个特性：创建 .ry 测试夹具 + .expected 文件 → 确认测试失败（RED）→ 实现代码生成（GREEN）→ 验证无回归

### QA Policy
由于 LLVM 在当前环境不可用，集成测试需要在有 LLVM 的环境中运行。每个任务的 QA 场景设计为可 agent 执行的步骤。

- **代码生成测试**: 使用集成测试运行器编译 .ry 文件并对比 stdout
- **运行时测试**: `cargo test -p ruyi_runtime`
- **回归检查**: 确认已有 5 个 codegen 测试仍通过
