# v0.3 运行时集成计划

## TL;DR

> **Quick Summary**: 将已完整实现的 GC 和 async 运行时连线到编译器 codegen，使 ruyic 输出链接了运行时的可执行文件。纯「连线」任务——运行时已就绪，只需对接。
>
> **Deliverables**:
> - 运行时静态库链接到产物二进制（driver + generator）
> - GC 分配接入 codegen（对象/数组/字符串走 ruyi_gc_alloc）
> - GC root 注册/注销 + write barrier（函数入口/出口 + 字段写入）
> - 异步状态机降级（state struct + poll + await 挂起/恢复）
> - spawn 内置函数
> - 异步 GC roots 注册
> - 异常传播端到端验证
>
> **Estimated Effort**: Large
> **Parallel Execution**: YES — 3 implementation waves, max 4 concurrent
> **Critical Path**: Link runtime → GC wiring → Async state machine → spawn → async roots

## Work Objectives

### Core Objective
将 ruyi_runtime（GC + async + exception）连线到编译器 codegen 和 linker，使 `ruyic` 输出的二进制携带运行时支持。

### Concrete Deliverables
- `crates/ruyi_runtime/Cargo.toml`: 添加 `crate-type = ["staticlib"]`
- `crates/ruyi_runtime/src/`: 新增 5 个 `extern "C"` GC 导出函数
- `crates/ruyic/src/codegen/builtins.rs`: 新增 root/barrier builtins 声明
- `crates/ruyic/src/codegen/expr.rs`: 对象/数组/字符串/类分配改走 `build_gc_alloc`
- `crates/ruyic/src/codegen/decl.rs`: 函数入口注册 root，出口注销 root
- `crates/ruyic/src/codegen/async_codegen.rs`: 完整状态机降级
- `crates/ruyic/src/driver.rs` + `generator.rs`: 链接 ruyi_runtime 静态库
- `crates/ruyi_runtime/src/async_runtime.rs`: 实现 `register_async_roots`

### Definition of Done
- [ ] `ruyic examples/hello.ry -o hello && ./hello` 成功输出 "Hello, Ruyi!"
- [ ] GC 分配的对象在函数返回后仍存活（root 注册生效）
- [ ] `async fn` 编译为可轮询的状态机
- [ ] `spawn(fn)` 启动绿色线程并执行
- [ ] `try/catch` 异常跨函数传播

### Must Have
- 产物二进制链接 ruyi_runtime 符号
- GC 分配覆盖所有堆对象（object/array/string/class/bigint）
- Stack root 注册/注销
- Write barrier 在字段写入后触发
- Async 状态机 struct + poll 函数
- `spawn(fn)` 函数可用
- `register_async_roots` 真实实现
- 所有现有测试通过（无回归）

### Must NOT Have (Guardrails)
- 不修改 parser、typechecker、lexer、macro_expand
- 不实现 Thread-local GC heaps (2.7)
- 不实现 DWARF 调试信息
- 不实现优化 PassManager
- 不修改 stdlib 链接机制
- 不添加 v0.3 范围外的特性
- 不在没有 LLVM 验证的情况下合并 codegen 修改
