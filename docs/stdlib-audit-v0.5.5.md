## Methodology

1. For implemented modules, the tool reads the source file and extracts every `export fn`, `export class`, `export trait`, and `export const` line (filtered by class name prefix when a single file backs multiple modules).
2. For each function body, the tool scans lines between the signature line and the matching closing brace for `TODO` comments or `unimplemented!()` markers. If those markers are the only content, the entry is flagged `STUB`.
3. For unimplemented modules, the tool reports the missing file path and notes that implementation is out of scope for v0.5.5.

Re-run with `cargo run -p audit-stdlib` from the workspace root to regenerate this file.
